### 2.3 Composite-FK tenant schema — validated & generated without a DB

Mini schema used (Tenant / Product / Order). `Product @@unique([tenantId, id])`, `Order.product @relation(fields: [tenantId, productId], references: [tenantId, id], onDelete: Restrict)`, `Order @@unique([tenantId, id]) @@unique([tenantId, orderNumber]) @@index([tenantId, dueDate])`, `quantity Decimal @db.Decimal(14,3)`, `dueDate DateTime @db.Date`.
`npx prisma validate` -> valid; `npx prisma generate` -> `Generated Prisma Client (7.10.0) to ./src/generated/prisma`
(files: `client.ts browser.ts enums.ts models.ts commonInputTypes.ts internal/ models/`).

Generated types facts that matter for `tenantDb`:
* `OrderWhereUniqueInput = Prisma.AtLeast<{ id?; tenantId_id?; tenantId_orderNumber?; AND/OR/NOT; tenantId?: StringFilter|string; productId?; ... }>`
  -> **extended where-unique is accepted**: `db.order.update({ where: { id, tenantId }, ... })`, `findUnique`, `delete` with
  non-unique fields alongside `id` all typecheck (verified).
* Compound unique selectors are named `tenantId_sku`, `tenantId_orderNumber`, `tenantId_id`.
* `OrderUncheckedCreateInput` **requires `tenantId`** when scalar FKs are used: `db.order.create({ data: { productId, ... } })`
  without `tenantId` is a TS error (verified: "Property 'tenantId' is missing"). So although the extension injects
  `tenantId` at runtime, **callers must still pass `tenantId` in `data`** (take it from the session; the extension overwrites
  it with the session tenantId anyway). Alternatively wrap creates in module helpers. Spec §2 must say this explicitly.
* Operation names present in generated types include `createManyAndReturn`, `updateManyAndReturn` — the extension handles them.
* Client import path: `import { PrismaClient, Prisma } from "@/generated/prisma/client"` (**not** `@prisma/client`).
  `Prisma.ModelName` enum, `Prisma.Decimal` available from there. Generated files carry `// @ts-nocheck` and `.ts`-extension
  imports; consumer tsconfig does **not** need `allowImportingTsExtensions` (verified both ways).

### 2.4 `src/lib/db.ts` — compiling tenant-scoping skeleton (tsc --strict exit 0; also built inside Next 16 and executed at runtime)

```ts
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient, Prisma } from "@/generated/prisma/client";

const connectionString = process.env.DATABASE_URL ?? process.env.NETLIFY_DB_URL;

function createPrisma() {
  if (!connectionString) throw new Error("DATABASE_URL is not set");
  const adapter = new PrismaPg({ connectionString });
  return new PrismaClient({
    adapter,
    log: process.env.NODE_ENV === "development" ? ["warn", "error"] : ["error"],
  });
}

const globalForPrisma = globalThis as unknown as { prisma?: ReturnType<typeof createPrisma> };
/** Raw, unscoped client. Only src/lib/auth/** and prisma/seed.ts may import this. */
export const prisma = globalForPrisma.prisma ?? createPrisma();
if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;

/** Every model that carries a tenantId column. Keep in sync with schema.prisma (unit test asserts this). */
export const TENANT_SCOPED_MODELS = new Set<Prisma.ModelName>([
  Prisma.ModelName.Product,
  Prisma.ModelName.Order,
  // ... User, Customer, ProductOperation, Material, BomItem, StockMovement, WorkCenter, ShiftCalendar, Shift,
  //     CalendarException, Machine, DowntimeWindow, ImportBatch, AuditLog
]);

const WHERE_OPS = new Set([
  "findMany", "findFirst", "findFirstOrThrow", "count", "aggregate", "groupBy",
  "updateMany", "updateManyAndReturn", "deleteMany",
]);
const UNIQUE_OPS = new Set(["findUnique", "findUniqueOrThrow", "update", "delete", "upsert"]);

type AnyArgs = Record<string, unknown>;

export function tenantDb(tenantId: string) {
  if (!tenantId) throw new Error("tenantDb: tenantId is required");
  return prisma.$extends({
    name: `tenant:${tenantId}`,
    query: {
      $allModels: {
        async $allOperations({ model, operation, args, query }) {
          if (!TENANT_SCOPED_MODELS.has(model)) return query(args);
          const a = (args ?? {}) as AnyArgs;

          if (WHERE_OPS.has(operation)) {
            a.where = { AND: [(a.where as AnyArgs) ?? {}, { tenantId }] };
          } else if (UNIQUE_OPS.has(operation)) {
            a.where = { ...((a.where as AnyArgs) ?? {}), tenantId };
            if (operation === "upsert") {
              a.create = { ...((a.create as AnyArgs) ?? {}), tenantId };
            }
          } else if (operation === "create") {
            a.data = { ...((a.data as AnyArgs) ?? {}), tenantId };
          } else if (operation === "createMany" || operation === "createManyAndReturn") {
            const data = a.data;
            a.data = Array.isArray(data)
              ? data.map((row: AnyArgs) => ({ ...row, tenantId }))
              : { ...((data as AnyArgs) ?? {}), tenantId };
          } else {
            throw new Error(`tenantDb: unsupported operation ${String(operation)} on ${model}`);
          }
          // query()'s parameter is the operation-specific args type; we widened it above.
          return query(a as never);
        },
      },
    },
  });
}

export type TenantDb = ReturnType<typeof tenantDb>;
```
Verified usage that compiles against this: `findMany` with caller `where`, `findUnique/update/delete` with `{ id, tenantId }`,
`upsert` with `tenantId_sku`, `create` with scalar FK + `tenantId`, `count`, `$transaction(async tx => tx.order.updateMany(...))`.
Raw escape hatches: `$queryRaw/$executeRaw` are **client-level**, not model operations, so `$allModels.$allOperations` never
sees them. To "throw for raw SQL through the scoped client" you must wrap them explicitly, e.g. return
`Object.assign(extended, { $queryRaw: () => { throw ... } })` is not type-safe — simpler and recommended: the review grep
(`\$queryRaw|\$executeRaw`) forbids them outside `prisma/`. Spec §2 wording should change accordingly.
Runtime check (Next 16 `next start`, unreachable DB): `tenantDb("x").order.count()` -> Prisma error
`Can't reach database server at 127.0.0.1:59999` — i.e. the client instantiates fine inside the Next server bundle.

## 3. Next.js 16 (docs read from `node_modules/next/dist/docs`, v16.3.4)

* **Request interception file:** `src/proxy.ts` (or root `proxy.ts`). Export **either** a named `export function proxy(request: NextRequest, event?: NextFetchEvent)` **or** a default export; not both. Config: `export const config = { matcher: [...] }` (same matcher syntax as before). `NextProxy` type available from `next/server`.
* **Runtime is Node.js and cannot be changed**: "The `edge` runtime is NOT supported in `proxy`. The `proxy` runtime is `nodejs`, and it cannot be configured." Setting `runtime` in proxy throws. So jose is fine, and technically Node APIs work — but on Netlify, Node middleware runs with restrictions (docs: "C++ Addons are not supported", "Filesystem is not supported"), and the proxy must stay DB-free for latency. Keep the spec rule: **no Prisma/bcryptjs in proxy**.
* `middleware.ts` still works but is **deprecated** (docs: "deprecated in Next.js 16 and renamed to proxy.js"); codemod `npx @next/codemod@canary middleware-to-proxy .`. Config flag rename: `skipMiddlewareUrlNormalize` -> `skipProxyUrlNormalize`.
* Build output labels it `ƒ Proxy (Middleware)` — verified in `next build`.
* **Async request APIs — sync access fully removed**: `cookies()`, `headers()`, `draftMode()`, `params` (layout/page/route/default/metadata files), `searchParams` (page) are Promises. Route handler signature: `GET(req, ctx: { params: Promise<...> })`. `npx next typegen` generates `PageProps`/`LayoutProps`/`RouteContext` helpers. Verified: `await cookies()`, `await headers()`, `await searchParams` compile and run.
* **Caching:** nothing to configure for a CRUD app. `cacheComponents` (PPR + `use cache`) is opt-in via `next.config.ts` `cacheComponents: true`; leave it **off** for M1. `experimental.dynamicIO`/`experimental.useCache` flags were removed. Pages that read `cookies()` are dynamic automatically.
* **Server Actions:** on by default. `experimental.serverActions.bodySizeLimit` default **1 MB** (applies to raw multipart body). CSV import of 2,000 rows × ~100 B ≈ 200 KB fits; set `bodySizeLimit: '4mb'` anyway to be safe for the upload action. `allowedOrigins` only needed behind a proxy with a different Host — not on Netlify.
* **serverExternalPackages:** `@prisma/client` and `pg` are already in the default externals list; `bcryptjs` and `jose` are pure JS and bundled fine (verified by build). No `next.config.ts` change required. The generated client under `src/generated/prisma` bundles under Turbopack (verified).
* `serverRuntimeConfig`/`publicRuntimeConfig` removed — use env vars. `next lint` removed — the repo's `eslint.config.mjs` + `"lint": "eslint"` is the Next 16 way.
* Node >= 20.9 required; repo netlify.toml already sets `NODE_VERSION = "22"`.
* Turbopack warns "inferred your workspace root" when multiple lockfiles are visible — irrelevant for the repo (single lockfile), but do not add a second lockfile anywhere under `~/Desktop/prodplan`.

### `src/proxy.ts` skeleton (compiled in `next build`; `curl /dashboard` -> `307 /login?next=%2Fdashboard`)

```ts
import { NextResponse, type NextRequest } from "next/server";
import { jwtVerify } from "jose";

const COOKIE = "pp_session";
const PUBLIC_PATHS = new Set(["/login", "/signup"]);

function secret() {
  const s = process.env.AUTH_SECRET;
  if (!s || s.length < 32) throw new Error("AUTH_SECRET must be set (>= 32 chars)");
  return new TextEncoder().encode(s);
}

async function readSession(req: NextRequest) {
  const token = req.cookies.get(COOKIE)?.value;
  if (!token) return null;
  try {
    const { payload } = await jwtVerify<{ tid: string; role: string; tv: number }>(token, secret(), {
      algorithms: ["HS256"],
    });
    return payload; // { sub, tid, role, tv, iat, exp }
  } catch {
    return null; // bad signature / expired
  }
}

export async function proxy(req: NextRequest) {
  const { pathname, search } = req.nextUrl;
  const session = await readSession(req);
  const isPublic = PUBLIC_PATHS.has(pathname);

  if (!session) {
    if (isPublic || pathname === "/") return NextResponse.next();
    const url = req.nextUrl.clone();
    url.pathname = "/login";
    url.search = `?next=${encodeURIComponent(pathname + search)}`;
    const res = NextResponse.redirect(url);
    if (req.cookies.has(COOKIE)) res.cookies.delete(COOKIE);
    return res;
  }

  if (isPublic || pathname === "/") {
    return NextResponse.redirect(new URL("/dashboard", req.url));
  }
  if (pathname.startsWith("/settings/users") && session.role !== "ADMIN") {
    return NextResponse.redirect(new URL("/dashboard", req.url));
  }
  return NextResponse.next();
}

export const config = {
  // Everything except Next internals, static assets and /api (route handlers do their own auth).
  matcher: ["/((?!api|_next/static|_next/image|favicon.ico|.*\\.(?:png|svg|jpg|jpeg|gif|webp|ico|css|js|map)$).*)"],
};
```
Note: `/api/health` is excluded by the matcher on purpose. The DB check (`isActive`, `tokenVersion`) happens in
`(app)/layout.tsx` / `requireRole`, not here. The JWT `tv` claim lets the proxy stay stateless.

### 4.2 What "Netlify DB" is in 2026 — the spec is written against the retired beta
* Netlify changelog 2026-04-13: "you cannot create new databases using the beta Netlify DB experience" (the Neon-extension beta with `NETLIFY_DATABASE_URL`, `netlify db init`, 7-day claim). GA followed the week of 2026-04-20.
* The GA product is **Netlify Database**: `netlify database init [--yes]`, package `@netlify/database`, env var **`NETLIFY_DB_URL`** (docs: "available across builds, agent runners, functions and edge functions"; `@netlify/database` source reads exactly `env.get("NETLIFY_DB_URL")`), optional `NETLIFY_DB_DRIVER=serverless`. Docs "Switch to Netlify Database": "The `NETLIFY_DATABASE_URL` environment variable from the legacy extension is no longer used."
* **No `NETLIFY_DATABASE_URL_UNPOOLED`, no 7-day claim, no Neon account** in the GA product. (Under the hood `@netlify/database` depends on `@neondatabase/serverless`, so it is Neon-compatible Postgres, but the branch/URL is managed by Netlify.)
* **Plans:** "available on Credit-based plans only" — this team is `credit-free`, and the DB is already enabled, so it works. Free-plan limits (docs billing page): 3 databases, 20 branches/db, 5 GB storage, compute min 1 / max 1 unit, **48 compute units per database per billing period** (10 credits/unit), database **sleeps after 5 min idle** (auto-scale/sleep configurable). Backups: 3-day on-schedule, last published deploy only. Storage free until at least 2026-07-01 (rates TBA). **Risk:** the 48-unit cap and cold-start after sleep affect a client staging review; document in DEPLOYMENT.md and warm the DB before demos. Exact unit semantics: UNVERIFIED (not defined in docs).
* **Branching:** "Production deploys are the only deploys that touch the production database"; "Deploy previews get their own database branch, with a copy of the production data taken when the deploy preview is first created". `getConnectionString()` "automatically point[s] to the correct database branch".
* **Migrations:** files in `netlify/database/migrations` (either `<digits>_<slug>.sql` or `<digits>_<slug>/migration.sql` — the latter is exactly Prisma's layout) are applied by Netlify "immediately before the deploy is published" (production) / "immediately before it becomes available" (previews); failure blocks the publish. **Bring-your-own tool:** "If you want to use your own migrations system, choose a different directory to avoid conflicts" and "apply production migrations via an out-of-band process". Prisma's `prisma/migrations` therefore does **not** collide. Do **not** point Prisma's `migrations.path` at `netlify/database/migrations` — Netlify would apply the SQL but Prisma's `_prisma_migrations` table would never be written, so `prisma migrate deploy/status` would try to re-apply.
* **Pooled vs direct:** Netlify exposes a single `NETLIFY_DB_URL`; docs say nothing about a pooler or an unpooled variant. Neon's Prisma guide says `prisma migrate` needs a direct (non `-pooler`) connection. Whether `NETLIFY_DB_URL` is pooled: **UNVERIFIED until the production branch exists** — inspect the host for `-pooler`; if migrate fails with prepared-statement/advisory-lock errors, fall back to applying `prisma migrate diff --from-migrations prisma/migrations --to-schema ... --script` output via psql, or use the Netlify migrations dir for staging only.
* **Local dev DB:** `netlify dev` starts a local Postgres-compatible DB and sets `NETLIFY_DB_URL` to it. ProdPlan uses its own Postgres 15 on :5433 via `DATABASE_URL`; do not run the app through `netlify dev`, use `next dev`.

* **zod 4.5.4** (`import { z } from "zod"`): `z.object({...}).safeParse(x)` -> `{ success: true, data } | { success: false, error: ZodError }`.
  Field errors: **`z.flattenError(error)`** -> `{ formErrors: string[], fieldErrors: { [field]: string[] } }` (v4 top-level helper);

  `jwtVerify<T>(token, secretBytes, { algorithms: ["HS256"] })` -> `{ payload }`; secret = `new TextEncoder().encode(AUTH_SECRET)` (Uint8Array).

## 8. Gotchas (all observed or cited above)

1. `prisma` `latest` is **8.0.0-rc.13**. Every install/`npx` must say `@7`. `typescript` latest is 7.0.2 — keep `^5`.
2. `prisma init` writes **`prisma7.config.ts`**; rename to `prisma.config.ts` (both are discovered; keep exactly one).
3. Prisma 7: no `url` in `datasource db {}`; `output` is mandatory; CLI does not load `.env` without `import "dotenv/config"` in the config file.
4. Import the client from `@/generated/prisma/client`, never `@prisma/client`. `Prisma.Decimal`, `Prisma.ModelName` live there too.
5. Scalar-FK `create` **requires `tenantId` in the TS input** even though `tenantDb` injects it — pass the session tenantId (the extension overrides it).
6. `$queryRaw/$executeRaw` are not model operations; the extension cannot intercept them — enforce by grep/lint, not at runtime.
7. `middleware.ts` is deprecated; use `src/proxy.ts` exporting `proxy` + `config.matcher`. Proxy runtime is **Node.js only**; `runtime` export throws.
8. All request APIs are async (`await cookies()`, `await params`, `await searchParams`); sync access is gone in 16.
9. Server Action body limit 1 MB by default — set `experimental.serverActions.bodySizeLimit` if the CSV upload is a server action.
10. **Netlify DB (Neon beta) is closed**; the GA "Netlify Database" uses **`NETLIFY_DB_URL`**, `@netlify/database`, `netlify database init --yes`, auto-migrations only from `netlify/database/migrations`. There is no unpooled URL and no Neon claim step.
11. The **production DB branch only exists after the first production publish**; `database status --branch production` errors/crashes before that. Deploy first, then migrate + seed.
12. `netlify deploy` builds by default; `--build` is not a flag in CLI 27 (`--no-build` is). Use `netlify deploy --prod --context production`.
13. Free credit plan: DB sleeps after 5 min idle and has a 48-compute-unit/period cap — expect a cold start on the first request of a demo.
14. shadcn 4.x defaults to **Base UI**; pass `-b radix -p nova`. `add form` produces nothing — use `field`. Components import from `radix-ui` and `cn` packages.
15. `@netlify/plugin-nextjs`: declare in netlify.toml, do not pin in package.json (Netlify guidance). Next 16 support is not named explicitly in Netlify docs — verify with the first deploy on day 1.
16. Do not add a second lockfile under the repo (Turbopack root inference warning) and do not run the app under `netlify dev` (it injects a local `NETLIFY_DB_URL`).
